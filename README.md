# Кибер-дерево знаний

Арт-объект для дня первокурсника. Студенты сканируют QR, пишут пожелание на учебный год, и после проверки модератором оно прилетает светящимся «чипом-листом» на дерево, выведенное на плазменную панель.

Дерево нарисовано как разводка печатной платы — это весь замысел, от него выводится каждое визуальное решение.

Мероприятие разовое, ~100 человек, 50–80 пожеланий, сентябрь.

## С чего начать

Нужен **Node 22.18 или новее** — проверить можно через `node -v`. Версия не случайная: скрипты в `scripts/` запускаются напрямую как `node scripts/shot.ts`, без отдельной сборки, а нативное срезание типов из `.ts` появилось только в 22.18. На Node 20 `npm run shot` и `npm run db:migrate` упадут с синтаксической ошибкой, хотя сам сайт соберётся.

```bash
npm install
npm run dev
```

Открыть http://localhost:3000 — там ссылки на все три поверхности.

**База данных для запуска не нужна.** Без `DATABASE_URL` проект поднимается на моках из `lib/db/mock.ts`: 25 готовых пожеланий, равномерно разложенных по специальностям из `config/specialties.ts`, с разными статусами и тремя флагами автомода. Это не заглушка на пять минут, а рабочий режим — по нему параллельно отлаживают форму, админку и дерево.

При старте в консоли будет видно, какой режим включился:

```
[db] DATABASE_URL пуст — работаем на моках из lib/db/mock.ts. Запись никуда не сохраняется.
```

## Три поверхности

| Путь       | Где открывается                          | Задача                   |
| ---------- | ---------------------------------------- | ------------------------ |
| `/form`    | телефон студента, по QR                  | отправить пожелание      |
| `/display` | ноутбук к панели по HDMI, Chrome в kiosk | показывать дерево        |
| `/admin`   | ноутбук модератора                       | подтверждать и отклонять |

Все три работают через один деплой на Vercel. Локальная сеть не нужна: телефоны идут через мобильный интернет.

## Переменные окружения

```bash
cp .env.example .env.local
```

| Переменная       | Зачем                                                 |
| ---------------- | ----------------------------------------------------- |
| `DATABASE_URL`   | строка подключения к Neon. Пустая — работаем на моках |
| `ADMIN_PASSWORD` | общий пароль для входа в `/admin`                     |

`.env.local` закрыт в `.gitignore` и в репозиторий не попадает. На проде значения задаются в настройках проекта Vercel.

## Подключение базы

1. Завести проект в [Neon](https://neon.tech), скопировать строку подключения.
2. Положить её в `DATABASE_URL` в `.env.local`.
3. `npm run db:migrate`

Миграции лежат в `db/migrations/` и написаны идемпотентно: повторный прогон на уже применённой базе ничего не ломает, отдельной таблицы версий нет.

## Кто что делает

Репозиторий делят два агента. Границы описаны в `AGENTS.md`, писать в чужую зону нельзя — это ломает параллельную работу.

| Зона                                                                                           | Кому принадлежит                     |
| ---------------------------------------------------------------------------------------------- | ------------------------------------ |
| `app/form/**`, `app/admin/**`, `app/api/**`, `lib/db/**`, `lib/automod/**`, `db/migrations/**` | бэкенд                               |
| `app/display/**`, `lib/tree/**`, `scripts/shot.ts`                                             | визуализация                         |
| `lib/types.ts`, `config/specialties.ts`, `package.json`                                        | общее, менять только по согласованию |

`lib/types.ts` — замороженный контракт. Против него пишется визуализация дерева, пока бэкенд наполняет роуты настоящей логикой. Если формат ответа API действительно надо поменять — сначала написать об этом, не менять молча.

Ветки: `feat/<зона>`, то есть `feat/backend` и `feat/display`. Влитие в `main` через PR, напрямую в `main` не коммитить.

## Жёсткие ограничения

Они не стилистические, они следуют из среды. Нарушение каждого ломает прод:

- **Вебсокетов нет.** Serverless не держит постоянные соединения. Обновление данных — только опросом раз в 2 секунды по курсору `updated_at`. Не предлагать Socket.IO, SSE, Pusher.
- **Состояния на сервере нет.** Между запросами в памяти ничего не живёт. Никаких синглтонов с кэшем, никаких очередей в памяти.
- **Файловой записи нет.** Только Neon. Ни SQLite, ни JSON на диске.
- **PixiJS импортируется только динамически, с `ssr: false`.** На сервере он падает. Каркас под это уже стоит: `app/display/tree-mount.tsx`.
- **Ничего не публикуется автоматически.** Автомод только проставляет `auto_flag`, решение всегда за человеком.
- **Ограничений по IP не ставить.** У мобильных операторов сотни абонентов за одним адресом — срежете половину зала.

## Конвенции

- Специальности — только из `config/specialties.ts`. От длины списка зависит число веток дерева, поэтому нигде больше не хардкодить. Разумный предел — 6.
- Цвета — только токены раздела 8 ТЗ. Четыре общих лежат в `app/globals.css`, акценты специальностей — в `config/specialties.ts` рядом с самими специальностями.
- Генерация дерева детерминированная, от seed. Один seed — одно дерево, иначе визуал не отладить по скриншотам.
- Интерфейс и комментарии в коде на русском.
- Формулы простым текстом, без LaTeX.
