# Кибер-дерево знаний — техническое задание

## 1. Что это

Арт-объект для дня первокурсника. На плазменной панели — светящееся дерево, собранное как разводка печатной платы. Студент сканирует QR, пишет имя, выбирает специальность и пишет пожелание на учебный год. После модерации пожелание прилетает на экран светящимся «чипом-листом» и закрепляется на ветке своей специальности.

Мероприятие разовое, ~100 человек, ожидается 50–80 пожеланий. Сентябрь.

## 2. Три поверхности

| Путь | Где открывается | Задача |
|---|---|---|
| `/form` | телефон студента, по QR | отправить пожелание |
| `/display` | ноутбук, подключённый к панели по HDMI, Chrome в kiosk | показывать дерево |
| `/admin` | ноутбук модератора | подтверждать и отклонять |

Все три работают через один и тот же деплой на Vercel. Никакой локальной сети не требуется — телефоны идут через мобильный интернет.

## 3. Стек и жёсткие ограничения

- Next.js (App Router) + TypeScript
- PixiJS v8 для дерева, 2D
- Neon (Postgres), доступ через `@neondatabase/serverless`
- Деплой на Vercel

**Ограничения, которые нельзя нарушать:**

- Никаких вебсокетов и Socket.IO. Среда serverless, постоянные соединения не живут. Обновление данных — только опросом.
- Никакого локального состояния на сервере. Между запросами в памяти ничего не сохраняется.
- Никакого SQLite и файловой записи. Только Neon.
- PixiJS импортируется только динамически, с `ssr: false`. На сервере он падает.

## 4. Модель данных

```sql
create table wishes (
  id          serial primary key,
  name        text not null,
  specialty   text not null,
  wish        text not null,
  status      text not null default 'pending',  -- pending | approved | rejected
  auto_flag   text,                             -- причина срабатывания автомода, null если чисто
  device_hash text,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);

create index wishes_updated_at_idx on wishes (updated_at);
create index wishes_status_idx on wishes (status);
```

`updated_at` обновляется при **любом** изменении строки — это курсор для опроса. Поставить триггер, а не полагаться на то, что все запросы его выставят вручную.

## 5. API

### `POST /api/wishes`
Тело: `{ name, specialty, wish, deviceHash }`.
Валидация, прогон через автомод, запись со статусом `pending`.
Ответ: `{ ok: true }` либо `{ ok: false, error }`.

### `GET /api/wishes?since=<iso>`
Публичный. Возвращает все записи с `updated_at > since`, включая их текущий статус:

```json
{ "wishes": [{ "id": 12, "name": "...", "specialty": "...", "status": "approved", "updatedAt": "..." }],
  "now": "2026-09-01T10:00:00.000Z" }
```

Клиент сам решает: `approved` — добавить или оставить, любой другой статус — убрать с экрана. Это одним запросом покрывает и появление, и снятие листа, и правку.

Текст пожелания отдавать здесь же — он нужен для всплывающей карточки.

Без `since` — отдать всё одобренное (первая загрузка).

### `GET /api/admin/queue?since=<iso>`
Требует авторизации. То же самое, но включая `pending` и `auto_flag`.

### `PATCH /api/admin/wishes/:id`
Требует авторизации. Тело: `{ status? , name?, specialty?, wish? }`.
Одобрение, отклонение, снятие с экрана (`approved` → `rejected`) и правка текста — всё через один эндпоинт.

### `GET /api/admin/export?format=csv|json`
Требует авторизации. Все записи целиком, для отчёта после мероприятия.

**Авторизация админки:** один общий пароль из `ADMIN_PASSWORD`, кладётся в httpOnly-cookie после ввода на `/admin`. Настоящая авторизация здесь не нужна и только съест время.

## 6. Автомодерация

Автомод ничего не публикует и ничего не удаляет сам. Он только выставляет `auto_flag`, чтобы модератор видел подозрительное сразу.

Проверки:
- длина: `name` 2–30 символов, `wish` 3–120 символов;
- мат по словарю, **с нормализацией**: перевод латинских омоглифов в кириллицу (`a o e p c x y k m h b t`), цифр в буквы (`0→о 3→з 4→ч 1→и 6→б`), схлопывание повторов букв, удаление пробелов, точек и дефисов между буквами. Без нормализации фильтр обходится за пять секунд;
- ссылки, `@упоминания`, номера телефонов;
- текст целиком капсом — не флаг, просто привести к нормальному регистру;
- дубликат текста уже существующего пожелания.

**Лимиты.** Одно пожелание на `device_hash` (UUID в localStorage телефона). Ограничение по IP ставить **не надо**: у мобильных операторов сотни абонентов сидят за одним адресом, вы срежете половину зала.

## 7. Панель модератора

Список карточек: имя, специальность, текст, время. Флагнутые автомодом — сверху и с красной рамкой, с указанием причины.

Управление: клик по карточке одобряет, крестик справа отклоняет.

**Обязательно горячие клавиши**, мышью в пик отправок не успеть:
- `Пробел` / `Enter` — одобрить
- `Delete` / `Backspace` — отклонить
- `↑` `↓` — переход между карточками
- `E` — правка текста перед публикацией
- `U` — снять с экрана уже опубликованное

Вторая вкладка — список опубликованных, чтобы можно было убрать то, что проскочило.

Звук на новую заявку. Учесть, что браузер не даст проиграть звук до первого клика по странице — показать кнопку «включить звук» и напомнить нажать её до начала мероприятия.

Опрос очереди — раз в 2 секунды.

## 8. Визуальное направление

Не «неоновое дерево вообще». Дерево нарисовано **как разводка печатной платы**: это и есть весь замысел, от него выводится каждое решение.

### Палитра

```
--bg          #060A14   глубокий сине-чёрный, паяльная маска
--copper-dim  #C88B3A   медь дорожек в тени
--copper-hot  #F0C070   медь под током
--silk        #E8E4D9   шелкография: логотипы, служебные подписи, без свечения
```

Акценты специальностей (по одному на ветку):

```
#4DE1C1  #FF6B9D  #7B9CFF  #FFD166  #B98CFF  #5FE07A
```

### Дерево

Ствол идёт снизу по центру. Ветви расходятся под углами, кратными 45°, как настоящие дорожки на плате: повороты срезаны фаской, а не скруглены, на стыках — круглые пятачки переходных отверстий. Толщина дорожки убывает с глубиной ветвления.

Количество магистральных ветвей = количеству специальностей. Каждая своего цвета. Точки крепления листьев рассчитываются один раз при генерации и раздаются по мере поступления пожеланий — снизу вверх, чтобы дерево заполнялось естественно.

Генерация детерминированная, от seed. Один и тот же seed даёт одно и то же дерево — иначе не отладить визуал по скриншотам.

### Лист

Силуэт микросхемы в корпусе: скруглённый прямоугольник с ножками по бокам, точкой первого вывода в углу, свечение по контуру в цвете специальности. Внутри — только имя, моноширинным шрифтом. Два размера, чередовать для живости.

### Момент прилёта — главный элемент

1. От корня по дорожке к точке крепления бежит импульс света (0.8–1.2 с). Дерево буквально проводит ток к новому листу.
2. В конце пути лист проявляется, коротко вспыхивает ярче нормы, оседает.
3. Одновременно поверх экрана — карточка с пожеланием целиком, крупно, на 6 секунд, затем уходит.

Всё остальное на экране должно быть тихим. Боевую яркость тратим только сюда.

### Покой

Между отправками экран не должен выглядеть зависшим:
- редкие фоновые импульсы тока по случайным дорожкам;
- еле заметное «дыхание» свечения листьев;
- раз в 20–30 секунд в углу негромко всплывает случайное старое пожелание, оформленное иначе, чем свежее;
- очень медленный дрейф камеры.

### Шрифты

- **Unbounded** — карточка пожелания, крупный текст. Есть кириллица, геометричный, характерный.
- **Golos Text** — форма, обычный текст.
- **JetBrains Mono** — имена на листах, счётчик, подписи специальностей. Моноширинный здесь не украшение: он из мира плат.

### Логотипы

Разместить как шелкографию у основания дерева: плоский цвет `--silk`, без свечения, без градиентов — именно так логотипы выглядят на настоящих платах. Это оправдывает их присутствие в кадре.

Файлы кладутся в `/public/logos/`. **Нужен SVG.** Растр в этой стилистике даст грязные края на панели.

### Технически

- Целевое разрешение 1920×1080. Если панель 4K — не увеличивать размер сцены, поднять `renderer.resolution`.
- Свечение через `AdvancedBloomFilter`, применяется только к слою дорожек и листьев. Шелкография и текст карточки — вне bloom, иначе поплывут.
- Держать 60 fps. При 100 листьях это не проблема, но bloom на весь экран в 4K — проблема, проверить заранее.

### Счётчик

В углу, моноширинным, тихо: `листьев на дереве: 47`.

## 9. Конфиг

`config/specialties.ts` — единственное место, где заданы специальности:

```ts
export const SPECIALTIES = [
  { id: 'isip', label: 'Информационные системы и программирование', color: '#4DE1C1' },
  { id: 'ib',   label: 'Обеспечение информационной безопасности',   color: '#FF6B9D' },
  { id: 'ssa',  label: 'Сетевое и системное администрирование',     color: '#7B9CFF' },
  // ЗАПОЛНИТЬ РЕАЛЬНЫМ СПИСКОМ. От длины списка зависит число веток.
] as const;
```

Разумный предел — 6 веток. Больше — дерево станет кашей, надо будет группировать.

## 10. Порядок работы

Каждый этап — отдельный коммит. Не браться за следующий, пока предыдущий не работает.

1. Каркас проекта, схема БД, `POST /api/wishes` и `GET /api/wishes`, автомод. Интерфейса нет, проверка через curl.
2. `/form` — форма, валидация, экран «спасибо», защита от повторной отправки.
3. `/admin` — авторизация, очередь, горячие клавиши, звук, правка, снятие с экрана.
4. `/display` — генерация дерева и статичная отрисовка. Листьев ещё нет.
5. `/display` — опрос, прилёт листьев, импульс тока, карточка пожелания, режим покоя.
6. Доводка визуала по скриншотам (см. ниже).
7. Экспорт и снимок дерева в высоком разрешении.

## 11. Цикл доводки визуала

Без этого дерево останется посредственным: по коду нельзя оценить, красиво ли получилось.

Скрипт `scripts/shot.ts` на Playwright: открывает `/display?seed=demo&mock=30`, ждёт стабилизации, сохраняет скриншот в `/tmp/display.png`. Режим `mock` наполняет дерево тестовыми листьями без обращения к БД.

Дальше — смотреть на картинку и править палитру, толщину дорожек, силу свечения, кривизну ветвления. Повторять, пока не станет хорошо.

## 12. Снимок и экспорт

- На `/display` клавиша `S` — выгрузка PNG через `renderer.extract` с двукратным разрешением. Для соцсетей колледжа после мероприятия.
- `/api/admin/export` — выгрузка всех пожеланий в CSV.

## 13. Чеклист дня мероприятия

- [ ] Залить 20–30 заготовленных пожеланий заранее. Дерево с тремя листьями выглядит грустно, и первые студенты не поймут, что происходит.
- [ ] QR ведёт на **короткую ссылку с редиректом**, а не напрямую на Vercel. Если что-то пойдёт не так, цель меняется за десять секунд вместо перепечатки плакатов.
- [ ] Ноутбук: сон отключён, уведомления отключены, автообновление системы отключено.
- [ ] Chrome в режиме киоска: `chrome --kiosk --disable-session-crashed-bubble <url>/display`
- [ ] Проверить масштаб на самой панели — на 1080p всё может оказаться мельче, чем на ноутбуке.
- [ ] Модератор нажал кнопку включения звука до начала.
- [ ] Проверено: `/display` пережидает обрыв интернета, не стирая дерево. Уже полученные листья хранятся в памяти клиента и не перезапрашиваются.
